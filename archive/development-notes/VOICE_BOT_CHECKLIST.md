# Voice Bot Checklist

هذه القائمة تلخّص ما يجب إنجازه في الـ voice bot حسب متطلبات المشروع الحالية في `spec.md` و `ai-service/AI_CHATBOT_ROADMAP.md`.

الهدف:
- تسليم voice chatbot بسيط، واضح، ومناسب للطالب داخل تطبيق Lisan.
- الصوت يجب أن يعمل من المتصفح.
- المحادثة تبقى مقيدة بمنهج العبرية للمبتدئين.

## 1. الأساس المعماري

- [ ] الواجهة الأمامية لا تتصل مباشرة بـ `ai-service`
- [ ] كل طلبات الشات النصية/الصوتية تمر عبر `Express Backend`
- [ ] `Express` يرسل الطلب إلى `FastAPI AI Service`
- [ ] حماية الاتصال الداخلي بين `Express` و `ai-service` عبر secret داخلي
- [ ] عدم كشف أي API keys في الـ frontend

## 2. تدفق الفويس المطلوب

- [ ] الطالب يفتح صفحة `/chatbot`
- [ ] يوجد زر مايك واضح لبدء التسجيل
- [ ] عند الضغط على المايك يبدأ الاستماع من المتصفح
- [ ] يتم تحويل الكلام إلى نص باستخدام `Web Speech API`
- [ ] النص الناتج يظهر للطالب قبل أو عند الإرسال
- [ ] النص يرسل إلى `POST /api/chat` عبر الـ backend
- [ ] يصل الرد النصي من المحرك
- [ ] يتم نطق الرد في المتصفح باستخدام `window.speechSynthesis`
- [ ] الرد يبقى ظاهر كنص داخل واجهة الشات

## 3. متطلبات الإدخال الصوتي

- [ ] استخدام `Web Speech API` للمحادثة الحرة
- [ ] طلب صلاحية الميكروفون بشكل واضح
- [ ] عرض حالة التسجيل:
- [ ] `idle`
- [ ] `listening`
- [ ] `processing`
- [ ] `error`
- [ ] دعم إيقاف التسجيل يدوياً
- [ ] معالجة حالة عدم توفر الميكروفون
- [ ] معالجة حالة رفض الإذن
- [ ] معالجة حالة عدم تعرف المتصفح على الكلام
- [ ] إذا فشل الصوت، يظل الطالب قادراً على الكتابة يدوياً

## 4. متطلبات الإخراج الصوتي

- [ ] استخدام `window.speechSynthesis` لنطق الرد
- [ ] اختيار صوت عبري مناسب إن وجد
- [ ] دعم سرعة قراءة طبيعية وبطيئة
- [ ] احترام إعداد `voiceSpeed` الموجود في الملف الشخصي إن كان مستخدماً
- [ ] منع تداخل قراءتين صوتيتين معاً
- [ ] وجود زر لإيقاف النطق الحالي
- [ ] عند وصول رد جديد، يتم إلغاء أي نطق سابق قبل بدء الجديد

## 5. متطلبات سلوك البوت

- [ ] الردود تبقى قصيرة ومناسبة لمستوى `A1`
- [ ] الردود تبقى بالعبرية داخل فقاعة الشات
- [ ] لا يوجد شرح عربي داخل البابل بشكل افتراضي
- [ ] fallback واضح عند الرسائل خارج النطاق
- [ ] إذا فشل الصوت، لا ينهار الشات النصي
- [ ] يمكن للطالب المتابعة كتابةً حتى لو تعطّل الصوت

## 6. واجهة المستخدم

- [ ] صفحة شات حقيقية وليست placeholder
- [ ] قائمة رسائل واضحة
- [ ] input نصي موجود دائماً
- [ ] زر إرسال نصي واضح
- [ ] زر مايك واضح
- [ ] مؤشر أن التطبيق "يسمع الآن"
- [ ] مؤشر أن النظام "يعالج الآن"
- [ ] مؤشر أن النظام "ينطق الآن"
- [ ] عرض fallback للمستخدم بشكل مفهوم
- [ ] التصميم مناسب للموبايل

## 7. الحفظ والاستمرارية

- [ ] حفظ رسالة الطالب الناتجة عن الصوت كنص داخل المحادثة
- [ ] حفظ رد المساعد كنص داخل المحادثة
- [ ] عند refresh لا تضيع المحادثة
- [ ] يمكن استرجاع المحادثات السابقة
- [ ] يمكن متابعة محادثة قديمة

## 8. الجودة والاختبار

- [ ] اختبار فتح صفحة الشات
- [ ] اختبار الضغط على المايك
- [ ] اختبار تحويل الكلام إلى نص
- [ ] اختبار إرسال النص الناتج إلى backend
- [ ] اختبار ظهور الرد
- [ ] اختبار نطق الرد
- [ ] اختبار fallback خارج المنهج
- [ ] اختبار انقطاع `ai-service`
- [ ] اختبار خطأ secret الداخلي
- [ ] اختبار refresh واسترجاع المحادثة
- [ ] اختبار على الموبايل
- [ ] اختبار على Chrome لأنه الأفضل لـ `Web Speech API`

## 9. ما يجب عدم فعله حالياً

- [ ] لا تستخدم `Azure TTS/STT` للمحادثة الحرة
- [ ] لا تبنِ voice pipeline مدفوع أو معقد الآن
- [ ] لا تضف multi-agent أو tool calling
- [ ] لا تحول البوت إلى general chatbot

## 10. أين نستخدم Azure فعلياً

- [ ] Azure Speech يبقى فقط في مسار `pronunciation assessment`
- [ ] لا نخلط بين "محادثة صوتية" و "تقييم نطق"
- [ ] إذا كان عندكم نشاط نطق منفصل، يبقى endpoint خاص به منفصل عن voice chat

## 11. تعريف الجاهزية للتسليم

نعتبر voice bot جاهزاً عندما:

- [ ] الطالب يستطيع فتح `/chatbot`
- [ ] يستطيع التحدث من المتصفح
- [ ] الكلام يتحول إلى نص
- [ ] النص يرسل عبر `Express`
- [ ] الرد يرجع من `ai-service`
- [ ] الرد يظهر كنص
- [ ] الرد يُنطق من المتصفح
- [ ] يوجد fallback واضح
- [ ] لا يوجد crash في السيناريوهات الأساسية

## 12. ترتيب التنفيذ المقترح

1. [ ] بناء Chat UI الحقيقي
2. [ ] ربط `POST /api/chat` عبر `Express`
3. [ ] إضافة voice input بـ `Web Speech API`
4. [ ] إضافة voice output بـ `speechSynthesis`
5. [ ] ربط حفظ المحادثات
6. [ ] اختبار end-to-end كامل

## 13. وضعنا الحالي تقريباً

- [x] محرك الشات في `ai-service` صار منظم ومستقر
- [x] fallback والـ cache والـ evals الأساسية موجودة
- [ ] Express gateway الكامل للفويس يحتاج تثبيت أو مراجعة نهائية
- [ ] Chat UI الصوتي الكامل غير منجز بعد
- [ ] voice flow end-to-end غير منجز بعد
- [ ] persistence الكامل لازم يتأكد منه مع واجهة الشات
